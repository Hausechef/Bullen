# Локальный Bullenhaus

Проект использует отдельный экземпляр `bullenhaus-local` в Docker Desktop.

| Сервис | Адрес |
| --- | --- |
| Приложение | http://localhost:3000 |
| HTTP API приложения | http://127.0.0.1:3001/api/health |
| Supabase API | http://127.0.0.1:54331 |
| PostgreSQL | 127.0.0.1:54332, база `postgres` |
| Supabase Studio | http://127.0.0.1:54333 |
| Локальные письма, Mailpit | http://127.0.0.1:54334 |

## Запуск

Из корня проекта:

```powershell
npm run dev:local
```

Скрипт запускает Docker и Supabase, настраивает совместимую версию Realtime,
проверяет привязку опубликованных портов к `127.0.0.1`, обновляет локальные
переменные окружения и запускает Vite и обработчики `api/**/*.ts` в фоне.
Уже запущенные процессы этого проекта используются повторно.

Требуются установленные Node.js, Supabase CLI, Docker Desktop и зависимости
workspace. Зависимости устанавливаются через `npx --yes pnpm@10 install --frozen-lockfile`.

## Что восстановлено

Источник: `D:\Новая папка\sgtmwdlycllbbavrqgzm\db_cluster-14-08-2026@08-43-18.backup.gz`.

- Все 30 таблиц приложения из архива, включая 13 533 лида и 95 транзакций.
- 20 аккаунтов Auth с исходными хэшами паролей и профилями.
- Функции PostgreSQL, ограничения, индексы, триггеры, политики RLS и публикации Realtime.
- 14 файлов `kyc-documents` и 3 файла `premarket_contracts` с проверкой SHA-256.
  Сохранены исходные владельцы, идентификаторы и даты объектов; версии физических
  файлов соответствуют локальному Storage.
- Настройка AI из `ai_settings`; серверный API использует её локальную копию.

Для текущего кода дополнительно применены миграция защиты изменения роли/KYC
и миграция таблиц `client_files`, `kyc_reviews` с приватным бакетом `client-files`.
Итого: 32 таблицы приложения, 15 функций в `public`, 106 политик доступа.

Edge Functions запускаются из существующих исходников:
`ai-chat`, `ai-status`, `crm-sync`, `crm-workers`, `data-export`.
Vite проксирует `/api` на локальный сервер, который исполняет те же 11 обработчиков,
что используются в Vercel. Вход для обычного локального Supabase проверяет реальный
пароль, включая адреса с `admin@`, `agent@` и `client@`.

## Данные и настройки

Данные хранятся в Docker volumes `supabase_db_bullenhaus-local` и
`supabase_storage_bullenhaus-local`. Другие локальные проекты не изменялись.

Локальные ключи находятся только в игнорируемых Git файлах:

- `artifacts/bullenhaus/.env.local` — адрес и публичный anon-ключ клиента.
- `.local/dev/server.env` — серверные ключи.
- `.local/dev/supabase-status.json` — параметры локального экземпляра.
- `.local/dev/frontend-before-local.env` — предыдущее подключение клиента.

Исходные бэкапы не изменены. Отчёты и рабочие файлы восстановления находятся
в `.local/restore/`; журналы серверов — в `.local/dev/`.
Перед обновлением Realtime сохранён дополнительный дамп
`.local/restore/before-realtime-upgrade.dump`.

## Совместимость и границы переноса

Образ Realtime закреплён на `public.ecr.aws/supabase/realtime:v2.130.0`:
версия CLI по умолчанию старее схемы Realtime в архиве.
На этом Docker Desktop настройки сети недостаточно для ограничения портов,
поэтому `scripts/local-services.mjs` явно задаёт адрес публикации, сохраняя volumes.

Архив не содержит настроек внешнего SMTP, OAuth и стороннего CRM.
Письма локальной среды остаются в Mailpit. `crm-sync` возвращает `skipped: true`,
пока не заданы `CRM_API_URL` и `CRM_API_KEY`. Ключ AI восстановлен, но платные
запросы к модели и отправка клиентских документов внешнему провайдеру не входят
в проверку восстановления.

Командный чат `TeamChat` по-прежнему ссылается на отдельный Next.js/Socket.IO backend,
исходников и данных которого нет в предоставленном проекте и бэкапе Supabase.

Исторические SQL-миграции в репозитории неполны. Автоматический reset/seed отключён
в `supabase/config.toml`; исходная база восстановлена из полного архива.
Для обычного перезапуска используйте `npm run dev:local`.

## Проверка восстановления

Количество строк совпало с архивом во всех 30 исходных таблицах. Хэши паролей всех 20 аккаунтов
сохранены; SHA-256 всех 17 файлов совпадает с исходниками и после перезапуска Storage.
Проверены вход клиента и администратора, разграничение доступа, защита изменения роли,
приватность KYC, локальные HTTP API, все пять Edge Functions и доставка изменения PostgreSQL
через Realtime авторизованному клиенту. Временные проверочные аккаунты удалены.

Проверки TypeScript для workspace и `api`, production-сборка клиента и 14 существующих тестов
прошли. Supabase security advisors не обнаружили проблем. Локальный запуск проверен командой
`npm run dev:local`; подробный отчёт — `.local/restore/verification-results.json`.
